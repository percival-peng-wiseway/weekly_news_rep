# 10 追踪表字段与信息权重

## 用途

定义跨模块统一的数据字典、可靠性和重要性评分、去重方法，使后续 Agent 产出可合并、可筛选、可审计。

## 核心来源

字段值来自对应模块的一手来源；本文件本身是内部规范。外部事实必须链接原始页面，不能只引用本追踪表。

## 追踪字段

所有模块使用下列“通用必填字段”，并按主题增加“模块扩展字段”。字段缺失时写明“未知”或“未披露”，不得凭空补齐。

## 通用必填字段

| 字段 | 格式/枚举 | 说明 |
|---|---|---|
| record_id | `AU-模块-YYYYMMDD-序号` | 永久唯一 |
| title | 文本 | 中性、具体，不复制宣传语 |
| event_date | YYYY-MM-DD/未知 | 事件发生日 |
| published_date | YYYY-MM-DD | 来源发布日 |
| retrieved_date | YYYY-MM-DD | Agent获取日 |
| module | 01–11 | 主模块；可加交叉标签 |
| jurisdiction | AU/VIC/NSW/QLD/SA/WA/TAS/ACT/NT | 可多选 |
| technology | 受控标签 | solar/wind/battery等 |
| status | 模块状态字典 | 如咨询、FID、COD |
| summary_facts | 1–5条 | 只写来源支持的事实 |
| impact | 正面/负面/混合/中性/待观察 | 必须说明对象 |
| time_horizon | 短期/中期/长期 | 短≤1年，中1–3年，长>3年 |
| primary_url | URL | 首选原始来源 |
| secondary_urls | URL列表 | 交叉验证 |
| source_type | 枚举 | 官方/监管/法定披露/研究/媒体等 |
| reliability | A/B/C/D | 证据等级 |
| verification | 已核验/单一来源/待核验/有冲突 | 核验状态 |
| supersedes | record_id/空 | 状态更新时指向旧记录 |
| notes | 文本 | 限制、口径和未决问题 |

## 模块扩展字段

- 新闻：公司、州、技术、事件类别、重要性。
- 政策：文件编号、咨询截止、生效日、预算、适用对象。
- 项目：开发商、坐标、MW、MWh、阶段、FID、COD、审批与并网。
- 市场：区域、时段、价格、负价、需求、发电组合、单位与数据版本。
- 融资：金额、币种、交易结构、PPA、资本开支、估值。
- 监管：规则编号、草案/最终决定、生效日、合规义务。
- 风险：并网、审批、融资、供应链、社区、环境、政治；概率与影响。

## 信息权重

默认顺序：

`法律/正式监管决定` ＞ `AEMO/AER/CER原始数据` ＞ `科研机构方法透明报告` ＞ `公司法定公告` ＞ `可靠通讯社/主流媒体` ＞ `专业媒体` ＞ `行业协会观点` ＞ `企业宣传/社交媒体`

评分建议：`综合优先级 = 影响力(1–5) × 0.4 + 可靠性(1–5) × 0.4 + 时效性(1–5) × 0.2`。若可靠性为 D，无论总分如何都不得列为已确认事实。

## 关键词

`source hierarchy`、`primary source`、`verification`、`materiality`、`supersedes`、`data revision`、`conflict`、`duplicate`、`methodology`。

## 更新频率

每次写入执行字段校验；每周处理待核验和冲突项；每月去重；每季度复核枚举与评分是否仍适用。

## 可靠性判断

- A：法律/正式决定/原始数据/审计或法定披露。
- B：官方说明、权威研究、可靠通讯社，方法或事实链清楚。
- C：专业媒体、协会、普通公司新闻稿，需要一手核验。
- D：观点、匿名消息、社媒或不可追溯汇总。

存在冲突时，不做“多数票”；比较证据层级、事件日期、口径和是否修订，并保留双方来源。
